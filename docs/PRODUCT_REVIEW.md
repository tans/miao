# MIAO 产品缺口评审

评审日期：2026-09-28  
依据：当前仓库的 `PRODUCT.md`、前端页面、Fastify API、PocketBase migrations 与本地安装/启动脚本。

## 结论

MIAO 已有一个可继续迭代的最小骨架：用户注册登录、个人工作区、应用和数据表、基础记录操作，以及浏览器内运行的 fx 助手。它还不是完整的企业内部工具搭建产品。当前最主要的缺口，是用户描述工作后还不能得到一个完整可供同事使用的工具；当前产品实际更接近“个人数据应用搭建器”。

产品文案应暂时把承诺限定为：**创建个人工作区，在其中搭建带数据表的轻量内部工具，并通过 AI 助手操作数据。** 若继续承诺“企业团队自助搭建工具”，需要补齐共享、权限、常用业务界面和部署治理。

## 当前已有能力

- 注册和登录；每个账号拥有一个工作区。
- 创建应用，并填写名称和用途说明。
- 创建包含有限字段类型的数据表；字段最多 24 个。
- 按字段类型浏览、新增、修改和删除记录；列表支持分页、搜索、排序和字段筛选。
- 工作区所有者可生成限时邀请链接并管理成员；成员能在工作区切换器中切换自己拥有或受邀加入的空间。
- fx 助手在浏览器 WebAssembly 环境运行，通过 MIAO API 提供的数据工具操作当前应用。
- AI Gateway 密钥通过服务端环境变量 `AI_GATEWAY_API_KEY` 配置；AI 请求经有会话认证和速率限制的 MIAO 服务端代理转发。
- PocketBase 保存用户、工作区、成员、邀请、应用、表元数据和业务记录；MIAO API 负责成员、应用和工作区范围的校验。

## 优先补齐

### P0：把首版产品承诺和实际结果对齐

现在创建应用只保存名称和描述，不会依据描述生成应用界面、数据结构或业务流程。AI 可以创建数据表和操作记录，但应用呈现目前主要是通用数据表页面。

需要明确首版交付是“轻量数据应用”还是“从描述生成内部工具”。建议先完成轻量数据应用闭环，再决定是否扩展到页面和流程生成。官网文案、空状态和 onboarding 应只承诺已经能完成的事情。

### P0：完成基本的数据维护闭环

- 新增/编辑记录已使用字段类型对应的表单控件，并在 API 层校验必填和数据类型。
- 数据表支持改名和删除、选项/关联/附件等字段类型，应用支持修改、归档/恢复和永久删除；现有字段定义仍不能修改。
- 当前支持文本、数字、日期、布尔、邮箱、网址、选项、关联和附件字段，并可配置必填；复杂字段的筛选条件和既有字段修改仍需完善。
- 记录列表支持分页、文本搜索、排序和单字段筛选；复杂字段类型的条件查询仍待扩展。

关系字段等复杂数据模型暂缓；下一步集中补齐现有字段定义修改和复杂数据类型。

### P0：完善企业统一 AI 凭据管理

已实现基础代理：浏览器使用 fx 自定义 `fetch` 访问 MIAO 代理，服务端校验登录会话和工作区，并只允许固定 Gateway 路径。平台管理员可在管理界面轮换密钥，密钥使用 `MIAO_SETTINGS_ENCRYPTION_KEY` 加密存于 PocketBase；若未配置管理密钥则沿用环境变量。工作区所有者可以设置每日请求预算，并查看持久化请求和 token 用量。代理还保留按用户和进程的内存速率限制。

仍需完善：按用户和进程的速率限制不适用于多实例；AI Gateway 返回流中的 token 用量可能不完整，需与账单核对。加密密钥需要安全备份与轮换方案。

另外，尚无模型选择或 JSPI 不可用时的替代路径。Onboarding 应说明当前模型和用量政策，并在不支持 JSPI 的浏览器中给出清晰提示。

### P0：完善个人工作区邀请与成员访问控制

已实现：每个用户保留自己的工作区，并可拥有多个受邀工作区；所有者可为邮箱生成 72 小时有效的一次性邀请链接、撤销邀请和移除成员。接受邀请要求登录或注册的邮箱与邀请邮箱一致。所有者和成员可使用当前工作区中的应用与数据；所有者负责管理成员。

当前邀请链接由所有者复制后自行发送，尚未接入邮件投递。暂不提供细分角色或应用级权限。所有业务 API 和 fx 代理都按用户当前选中的工作区重新校验成员身份；上线前需验证成员移除后立即失去访问能力。

## 上线前需要补齐

- **注册与账号生命周期：** 邮箱验证和密码重置需配置邮件服务；注册策略/域名限制已支持环境变量配置；注册/重置限流和管理员代为停用入口仍缺失。用户可以自行停用或永久删除账号。工作区邀请仍由所有者复制链接后自行发送。
- **数据安全与治理：** PocketBase 数据备份、恢复演练、保留策略、管理员操作审计和用户数据导出。旧备份脚本随 Mongo/旧栈移除后，当前仓库未提供 PocketBase 备份流程。
- **访问边界：** PocketBase 系统凭据和 AI Gateway 长效密钥只在服务端使用；PocketBase 的宿主机管理端口保持不公开。所有业务接口都要验证用户、工作区成员、应用和记录之间的归属关系。
- **部署与故障处理：** 环境变量配置、首次启动、PocketBase 初始化、升级/migration、备份恢复、HTTPS/反向代理、日志与故障排查说明。
- **验证：** 注册登录、跨工作区访问隔离、动态建表、字段校验、记录 CRUD、fx 不支持 JSPI、PocketBase 不可用等关键路径尚未形成自动化验收。

## 文档现状

仓库当前有 `PRODUCT.md` 和本评审文档。`PRODUCT.md` 用于说明产品方向、边界和架构职责；本文件记录当前差距和建议优先级。

目前还没有面向使用者的快速开始/帮助文档、API 参考、部署运维手册、数据备份恢复流程或版本路线图。因此产品方向有文档记录，交付和运维文档尚未齐备。

## 建议顺序

1. 对齐“轻量数据应用”首版承诺和 onboarding。
2. 补全字段类型正确的记录新增、编辑、删除和校验。
3. 增加记录分页、搜索、排序；完善表与应用的编辑/归档。
4. 完善企业密钥轮换、可观测性和组织级持久化用量限额。
5. 加入邀请邮件投递，并验证跨工作区隔离及移除成员后的即时失权。
6. 发布前补齐备份恢复、部署手册和关键权限验收。

## 用户主流程交付优先级

目标路径：**注册/登录 → 创建/修改应用 → fx 构建 → 使用应用 → 日常工作台首页**。优先级按“阻断用户完成一次可用工作”的程度排序。下表用于迭代排期与验收；“已落地”只表示仓库当前实现，不代表尚未完成的发布治理。

| 优先级 | 阶段 | 当前状态 | 交付与验收标准 |
| --- | --- | --- | --- |
| P0 | 注册/登录 | 已有注册、登录、退出、邀请邮箱校验、可选邮箱验证、密码重置、账号停用/删除；注册策略可配置 | 新用户可创建账号并进入自己的工作区；已注册用户登录后恢复工作区；无效凭据有明确反馈；刷新后会话可恢复；邀请必须由匹配邮箱接受；开启邮箱验证时完成验证才能登录；停用需密码确认，删除需再次输入密码和邮箱确认。 |
| P0 | 创建/修改应用 | 已有创建、名称/说明编辑、归档/恢复、永久删除确认 | 创建后立即进入应用；从应用页可修改名称和用途说明并保存；归档后可从工作台恢复；永久删除前说明影响并二次确认。 |
| P0 | fx 构建 | 浏览器内 fx 已有建表、查表和记录操作工具；JSPI、AI Gateway 未配置时给出状态/错误；引导及构建反馈需持续完善 | 在应用内描述业务后可让 fx 先检查现有表，再创建字段类型明确的数据表；工具调用状态和失败原因可见；浏览器不支持 JSPI 或 AI 未配置时提供清楚提示；AI 写入数据前确认用户提供的值。 |
| P0 | 使用应用 | 已有类型化记录新增、编辑、删除、校验、分页、搜索、排序和筛选；支持选项、关系和附件字段；现有字段不可编辑 | 用户可浏览表、按字段类型新增和修改、删除记录；附件下载经 MIAO 认证代理；关联记录校验当前应用和工作区；跨工作区访问被拒绝。 |
| P0 | 日常工作台首页 | 本次补齐为登录后的默认页，展示应用、工作区、AI 状态和继续工作入口 | 登录后先看到工作台；应用卡片可直接打开；无应用时有明确创建引导；创建入口始终可达；切换工作区后内容随工作区更新。 |
| P1 | 工作区协作 | 邀请链接、成员管理已实现；邮件投递、应用级权限缺失 | 邀请邮件能投递并展示状态；移除成员后立即失去访问权限；成员角色和可操作范围有明确规则。 |
| P1 | 数据工作能力 | 已实现分页、搜索、排序、筛选、表改名/删除及常见字段类型；现有字段定义不可修改 | 支持安全地改字段和复杂条件查询；变更字段需说明对既有数据的影响。 |
| P1 | fx 治理 | 已有管理员密钥轮换、服务端加密存储、持久化用量统计和工作区每日预算；每用户/进程速率限制仍是内存计数 | 完成多实例共享速率限制；核对 Gateway token 统计准确性；建立加密密钥备份和轮换流程。 |
| P2 | 上线运营 | 部署说明已有；备份恢复、审计、导出、自动化关键路径验收缺失 | 提供定期备份与恢复演练流程、审计记录和数据导出；形成注册、隔离、CRUD、fx 失败状态的发布验收记录。 |

### 本次交付记录

- 登录后默认进入日常工作台，不再自动把用户带进第一款应用。
- 工作台列出当前工作区的应用、更新时间、工作区数量和 fx 配置状态；空工作区提供创建入口。
- 增加应用修改入口，名称与用途说明可保存；API 只更新请求中提供的字段，并继续校验当前工作区归属。
- 应用创建与修改共用表单；应用页可返回首页继续选择其他应用。
- 应用可归档、恢复或永久删除；删除前告知会同时删除表和记录。
- 记录列表支持服务端分页、文本搜索、排序和字段筛选；数据表支持改名和删除。
- 增加可选邮箱验证、密码重置、受邀/关闭注册策略、允许邮箱域名限制和账号删除流程。
- 增加经密码确认的账号停用流程；停用保留数据，账号删除会清理所属工作区和业务数据。
- 增加平台管理员 AI Gateway 密钥轮换与加密存储、工作区每日预算和持久化请求/token 用量查看。

### 落地顺序

1. **当前迭代：P0 主路径**——工作台、应用创建/修改、fx 首次构建引导、记录 CRUD、工作区访问隔离及失败状态。
2. **下一迭代：P1 可持续日常使用**——记录分页和检索、schema 管理、邀请邮件、Gateway 用量治理。
3. **发布治理：P2**——账号找回与验证、备份恢复、审计/导出、发布前关键路径验收。
