# MIAO 产品缺口评审

评审日期：2026-09-28  
依据：当前仓库的 `PRODUCT.md`、前端页面、Fastify API、PocketBase migrations 与 Docker Compose。

## 结论

MIAO 已有一个可继续迭代的最小骨架：用户注册登录、个人工作区、应用和数据表、基础记录操作，以及浏览器内运行的 fx 助手。它还不是完整的企业内部工具搭建产品。当前最主要的缺口，是用户描述工作后还不能得到一个完整可供同事使用的工具；当前产品实际更接近“个人数据应用搭建器”。

产品文案应暂时把承诺限定为：**创建个人工作区，在其中搭建带数据表的轻量内部工具，并通过 AI 助手操作数据。** 若继续承诺“企业团队自助搭建工具”，需要补齐共享、权限、常用业务界面和部署治理。

## 当前已有能力

- 注册和登录；每个账号拥有一个工作区。
- 创建应用，并填写名称和用途说明。
- 创建包含有限字段类型的数据表；字段最多 24 个。
- 浏览、添加和删除记录；API 已支持更新记录。
- fx 助手在浏览器 WebAssembly 环境运行，通过 MIAO API 提供的数据工具操作当前应用。
- PocketBase 保存用户、工作区、应用、表元数据和业务记录；MIAO API 负责应用范围及工作区范围的校验。

## 优先补齐

### P0：把首版产品承诺和实际结果对齐

现在创建应用只保存名称和描述，不会依据描述生成应用界面、数据结构或业务流程。AI 可以创建数据表和操作记录，但应用呈现目前主要是通用数据表页面。

需要明确首版交付是“轻量数据应用”还是“从描述生成内部工具”。建议先完成轻量数据应用闭环，再决定是否扩展到页面和流程生成。官网文案、空状态和 onboarding 应只承诺已经能完成的事情。

### P0：完成基本的数据维护闭环

- 前端新增记录使用逐字段 `window.prompt`，没有按数字、日期、布尔等字段类型呈现控件，也没有字段级校验。
- 前端没有编辑记录入口，尽管 API 支持更新。
- 数据表创建后不能编辑字段或删除数据表；应用也不能删除或归档。
- 字段目前只能从受限类型中选择；没有关系字段、选项字段、文件字段或必填设置的完整交互。
- 记录列表一次性读取整张表，没有分页、搜索、排序或筛选；记录数增长后会影响响应时间和页面可用性。

建议先完成类型正确的新增/编辑/删除与必填校验，再加入分页、搜索和排序。关系字段等复杂数据模型暂缓。

### P0：接入企业统一 AI 凭据

产品决策：AI 凭据由企业统一配置。当前实现仍要求每位用户自行输入 Vercel AI Gateway Key，密钥仅保存在页面内存中；这与产品决策冲突。

fx 浏览器 SDK 支持自定义 `fetch`。前端应通过此接口把 Gateway 请求发送到 MIAO 服务端代理，由服务端添加企业密钥后转发。长效密钥必须只在服务端配置，不能返回浏览器。代理需校验用户会话、限制可访问的上游路径和请求方法、设置用量限额，并提供连接失败提示。企业密钥的配置入口（环境/密钥管理服务或受限的管理页面）仍需定稿。

另外，尚无模型选择或 JSPI 不可用时的替代路径。Onboarding 应说明当前模型和用量政策，并在不支持 JSPI 的浏览器中给出清晰提示。

### P0：个人工作区邀请与成员访问控制

产品决策：个人工作区可以邀请其他用户。当前实现仍只有工作区所有者，没有成员、邀请或协作者权限；其他同事不能共享和使用同一个工具。

首版建议采用最小权限模型：所有者可邀请和移除成员；成员可使用工作区内应用及数据。邀请需绑定邮箱、限时且只能接受一次。注册登录和每个 API 请求都要解析成员关系，并对应用、数据表和记录执行工作区隔离校验。暂不引入细分角色和应用级权限。

## 上线前需要补齐

- **注册与账号生命周期：** 邮箱验证、忘记密码、账号停用/删除、注册限流，以及企业如何控制谁能注册。
- **数据安全与治理：** PocketBase 数据备份、恢复演练、保留策略、管理员操作审计和用户数据导出。旧备份脚本随 Mongo/旧栈移除后，当前仓库未提供 PocketBase 备份流程。
- **访问边界：** PocketBase 系统凭据和 AI Gateway 长效密钥只在服务端使用；PocketBase 的宿主机管理端口保持不公开。所有业务接口都要验证用户、工作区成员、应用和记录之间的归属关系。
- **部署与故障处理：** 环境变量配置、首次启动、PocketBase 初始化、升级/migration、备份恢复、HTTPS/反向代理、日志与故障排查说明。
- **验证：** 注册登录、跨工作区访问隔离、动态建表、字段校验、记录 CRUD、fx 不支持 JSPI、PocketBase 不可用等关键路径尚未形成自动化验收。

## 文档现状

仓库当前有 `PRODUCT.md` 和本评审文档。`PRODUCT.md` 用于说明产品方向、边界和架构职责；本文件记录当前差距和建议优先级。

目前还没有面向使用者的快速开始/帮助文档、API 参考、部署运维手册、数据备份恢复流程或版本路线图。因此产品方向有文档记录，交付和运维文档尚未齐备。

## 建议顺序

1. 对齐“轻量数据应用”首版承诺和 onboarding。
2. 补全字段类型正确的记录新增、编辑、删除和校验。
3. 增加记录分页、搜索、排序；完善表与应用的编辑/归档。
4. 移除用户自带 AI Key 输入，加入服务端 Gateway 代理、企业密钥配置和用量限制。
5. 加入邀请、成员列表和所有者/成员两级权限，并验证跨工作区隔离。
6. 发布前补齐备份恢复、部署手册和关键权限验收。
