# MIAO Agent-first 后台与工作台交付方案

更新日期：2026-09-29  
状态：工作台首页入口已完成第一轮改造；应用运行时和 fx 版本生命周期待实施

## 1. 目标与已确认边界

本方案以用户提供的《MIAO-Agent-First-后台功能规格》为产品目标，以 `miao-dashboard-preview.svg` 为布局参考，并以当前仓库代码、已有权限规则和运行方式为实现基线。附件里的应用名称、业务记录、统计数字、在线状态等均为演示内容，不视为线上事实或执行指令。

重点推进两个互相隔离的工作面：

1. **平台级后台**：管理账号、工作区、应用元数据、AI 服务和汇总用量。平台后台只看元数据与汇总数据，不直接查看业务记录、附件内容或 fx 对话正文。
2. **用户工作台**：登录后默认进入应用工作台。fx 对话保留为独立导航入口；用户主要通过已发布的应用界面处理业务。

工作台遵循三个清晰的任务边界：

- 用 fx 创建、修改、预览和发布应用；不增加与 fx 并行的可视化建应用流程。
- 在发布后的业务界面中日常查看、录入、搜索和更新业务信息。
- 需要排查结构或修正记录时，再从应用的次级入口进入数据表检查页。

保留当前已确认的租户隔离、服务端权限检查和平台元数据边界。所有界面状态必须来自真实服务端数据；不展示虚构的运行状态、最近使用时间、业务缩略图或统计值。

## 2. 目标信息架构

### 平台级后台

- 独立平台后台，不混入普通工作区导航。
- 页面包括总览、用户、工作区、应用目录、AI 用量、平台审计和 AI 服务。
- 用户/工作区/应用查询按需分页；平台管理员不能通过页面、fx、附件或深链接读取业务内容。
- 修改账号状态等全局操作必须带原因、明确确认并进入平台审计。

### 用户工作台

- 左侧导航承载 MIAO、工作区切换、概览、应用、最近使用、空间设置和账号；小屏适配为紧凑导航/抽屉。
- 概览首屏只突出「今天想做什么？」和一个 fx 多行输入区；支持键盘发送，提交中禁用重复发送。
- 应用卡片展示实际名称、用途、已知发布/草稿状态及真实更新时间；缩略图只能使用脱敏预览。后端尚无对应数据时隐藏该项，不编造值。
- 空状态只提供「描述你想做的应用」这个主行动。移除统计卡和“创建→建表→使用”教学区。
- 应用首页默认是已发布业务界面。数据表与记录管理移入应用的次级「查看数据表」入口。
- 应用页 fx 修改需要生成独立草稿和变更摘要；预览不得写入正式业务数据；发布要由服务端校验权限、定义、引用和版本冲突后原子生效。
- Viewer 只获得授权范围内的只读操作；危险操作要明确对象与影响并在服务端复核。

## 3. 当前差距与首轮调整

| 区域 | 当前实现 | 目标调整 | 处理方式 |
| --- | --- | --- | --- |
| 工作台首页 | 原有统计卡、应用目录、单独创建按钮、创建步骤说明 | fx 输入为主、应用预览为次；空状态单一主行动 | 已移除统计/说明和并行创建入口；首页输入复用现有 fx 对话 |
| 应用卡片 | 名称、用途、更新时间；暂无版本/发布信息 | 增加真实版本/发布信息和脱敏结构预览 | 当前只呈现真实元数据；等版本运行时数据可用后再显示状态，不伪造缩略图 |
| 应用详情 | 默认直接呈现数据表和记录管理器 | 默认进入已发布业务界面，数据检查次级进入 | 下一步先设计并实现受限、版本化 UI 定义和只读运行时，再迁移默认入口 |
| fx | 浏览器内对话和现有数据工具，无会话持久化/版本生命周期 | 工作区或应用绑定的对话、提案、草稿、预览、发布和版本回退 | 逐步增加 API、定义校验、授权、并发控制和明确状态 |
| 数据结构管理 | 页面提供直接新建/字段编辑流程 | 低频检查/修复入口；结构设计由 fx 引导 | 保留兼容性与服务端授权，不扩展拖拽式低代码设计器 |
| 平台管理 | 元数据与汇总后台已建立 | 持续保持与用户运行时隔离 | 在后续验收中持续验证管理员接口不泄露业务记录 |

## 4. 逐步交付顺序

每一步只交付一个可审查的纵向增量；完成代码修改后创建 Git 提交，并更新本文的状态。按仓库 `AGENTS.md` 用项目 PM2 配置管理服务；不启动另一个常驻服务。只有用户明确要求时才增加或运行自动化测试。

### A. 工作台入口与文案校准（已完成，提交 `6b228d4`）

- 首页增加 fx 多行输入并复用现有对话提交能力；Enter 发送、Shift+Enter 换行，发送期间禁用两处输入。
- 移除首页统计、教学步骤和独立手工创建应用主流程；应用创建统一从 fx 发起。
- 首页只显示应用名称、用途与可用更新时间；空工作区文案指向首页输入，不重复增加创建按钮。
- fx 仍是导航中的独立入口，概览与 fx 导航分别显示当前选中态。

**验收：** 登录默认仍在工作台；首页输入复用既有 fx 提交流程并切换到对话；空状态只有首页输入这一个主行动；工作区切换仍清理旧上下文；首页不展示无来源的计数、运行状态或预览。

### B. 应用运行时与数据检查降级

- 定义版本化的有限 UI 描述格式和允许的业务组件清单；不允许运行模型任意 JavaScript。
- 为新旧应用区分未发布、草稿、已发布、发布失败和已归档状态。
- 应用主路由优先渲染已发布界面；没有已发布界面时明确说明状态，并保留进入数据检查页的入口。
- 数据列表默认只读浏览；可写用户明确切换编辑并看到保存结果。表结构变更引导 fx。

**验收：** 已发布界面刷新后稳定；空数据有真实空状态；无版本应用不显示为运行中；数据检查仍使用当前 API 授权。

### C. fx 草稿、预览、发布与回退

- 新增应用提案、界面变更、预览、发布和版本列表 API/工具。
- fx 按当前工作区/应用绑定上下文，展示实际工具执行状态、变更摘要和可恢复错误。
- 发布前服务端验证定义、字段/表引用、发布权限和起草版本；成功时原子更新，失败不影响当前发布版。
- 预览只读真实数据或使用隔离示例数据；不可隐式写业务数据。

**验收：** 新应用从自然语言走到预览与显式发布；发布失败保留草稿与旧版本；并发冲突不会静默覆盖；只回退兼容的纯 UI 版本。

### D. 业务组件、工作区隔离和权限可靠性

- 先实现表单、列表/表格、详情、过滤和操作按钮等有限组件，按应用真实数据绑定。
- 每个写入动作走现有服务端校验并提供成功、失败、验证、重试和重复提交反馈。
- owner/应用管理者可按权限管理和发布；viewer 对 UI、fx、数据页和直接 API 请求均不能越权写入。
- 应用切换、工作区切换、成员授权变化时清除或重新校验旧页面、应用和对话上下文。

**验收：** 录入后刷新仍存在；跨工作区读取失败；viewer 的界面和直接请求都不能写入；AI/JSPI 失败不影响已发布应用。

### E. 会话、版本历史和交付验收

- 持久保存工作区创建会话和应用会话；私人对话默认不向其他成员展示。
- 补上最近使用、搜索/排序（应用规模需要时）、变更历史、纯界面版本回退和安全缩略预览。
- 更新 API、产品评审、部署与操作文档；完成目标环境、多个角色和真实账号的人工验收。

**验收：** 重新登录可恢复授权会话；版本变更可追溯；卡片缩略预览不包含真实业务记录；管理员元数据范围不变。

## 5. 明确暂不做

- 拖拽组件编辑器、字段配置向导、工作流画布或独立手工建应用主流程。
- 模型生成代码在 MIAO 主站源下直接执行。
- 平台管理员代入用户身份或直接打开业务记录、附件和对话正文。
- 在没有真实数据前展示运行状态、模拟业务内容、假健康状态或“最近使用”。
- 未验证真实任务需求前扩展复杂流程和协作审批。
