# 平台后台与用户工作台产品方案

状态：平台后台与基础工作台阶段 0–4 已实现；Agent-first 工作台后续计划见[专项方案](AGENT_FIRST_PRODUCT_PLAN.md)；阶段 5 的目标环境验收待完成
更新日期：2026-09-29

## 1. 产品目标

MIAO 面向企业内部工具的协作场景，需要交付两个相互独立、权限清楚的工作面：

1. **平台级后台**：平台运营人员处理账号、工作区、应用元数据、平台 AI 配置和全局用量问题。
2. **用户工作台**：企业员工切换工作区、发现和管理应用、进入应用维护数据，或打开 fx 助手继续协作。

平台管理员处理支持问题时默认只查看账号、工作区、应用元数据、配置状态和汇总用量，不查看业务记录、附件内容或对话正文。支持人员需要了解业务数据时，由用户自行导出并分享。

用户登录后默认进入应用工作台；fx 对话是工作台中的独立主入口，不再替代应用导航和数据页面。

## 2. 初始代码基线与当前状态

- 服务端是 Bun + Fastify，持久化数据使用 PocketBase，前端为原生 JavaScript；继续沿用现有技术栈。
- 平台管理员由 `MIAO_ADMIN_EMAILS` 环境变量按邮箱确定。初始代码只有 AI Gateway 配置 API；本次为该角色增加平台目录、汇总用量、运行状态、账号状态管理和审计 API。
- 工作区的成员、邀请、角色、应用权限、用量、预算、导出和操作日志 API 已有部分实现。
- 初始代码中，登录后的 `workspace` 只渲染 fx 对话；本次恢复了工作区选择器、应用目录、首页、数据表/记录视图，并将 fx 助手放到独立导航入口。
- 初始管理弹窗没有主流程入口；本次增加平台后台总览、用户、工作区、应用目录、AI 用量、平台审计和 AI 服务页面，并接入平台管理 API。
- 初始静态 HTML 缺少 `#table-list` 和 `#records-root`，但前端数据表和记录渲染逻辑仍会写入这些节点；现已补齐页面并恢复手动数据操作。
- 现有平台审计与工作区操作日志分开展示；工作区日志已支持分页，平台日志支持目标类型/ID筛选。

## 3. 信息架构

### 平台后台

独立的 `/admin` 页面区域或等效路由，只有通过服务端平台管理员校验的账号才能进入。后台使用全局导航：

- **总览**：账号、工作区、应用数量；今日及近期 AI 请求数、token 汇总、成功率/失败数；各模块链接到明细。
- **用户**：搜索、分页查看账号元数据与状态；平台管理员可停用或恢复账号。停用和恢复都要填写原因并确认。
- **工作区**：搜索、分页查看工作区名称、所有者、成员数、应用数、创建时间和状态。
- **应用目录**：跨工作区查看应用名称、所属工作区、归档状态、表数量和时间等元数据。不返回记录、附件、描述中可能包含的工作内容或对话正文。
- **AI 服务**：展示 provider、模型、配置来源、密钥是否已配置及掩码提示；可轮换管理界面密钥或回退服务器环境密钥。绝不返回完整密钥。
- **平台审计**：记录平台管理员执行的账号状态、AI 配置和其他全局管理操作，支持分页与目标过滤。

运行时环境变量（如注册模式、允许邮箱域、邮件服务、加密密钥和数据目录）由部署运营方维护。后台可展示非敏感配置状态和配置来源；不得展示密钥明文，也不在首期提供任意环境变量编辑器。

### 用户工作台

普通用户登录后默认进入工作区首页。工作台左侧或移动端抽屉承载导航：

- 工作区切换器；切换后刷新成员角色、应用权限、应用列表和可见内容。
- **工作台首页**：当前空间名称、可用应用和必要的空状态；提供创建应用入口。
- **应用列表**：显示当前用户可访问的未归档应用，支持打开；owner 可管理归档、恢复与永久删除。
- **fx 助手**：保留独立对话视图；创建或激活应用后显示当前上下文。JSPI 或 AI 服务不可用时仍可从应用页手动维护数据。
- **应用数据页**：列出数据表、查看与搜索/筛选记录、分页、新增/编辑/删除记录，以及按角色呈现表结构管理和应用权限入口。
- **工作区管理**：成员、邀请、角色、应用访问权限、AI 用量/预算、JSON 导出与操作日志。只向有权限的 owner/admin 显示相应入口；服务端继续逐请求授权。
- **账号**：个人资料与退出、停用或删除账号入口；不可用操作说明清楚，危险操作再次确认。

保持现有 MIAO 绿色主题、猫咪品牌资产和 DaisyUI 组件习惯。优先恢复有证据的既有工作台结构，不另起产品视觉系统。

## 4. 权限与隐私规则

| 操作 | 平台管理员 | 工作区 owner | 工作区 admin | member |
| --- | --- | --- | --- | --- |
| 查看全局账号/工作区/应用元数据与汇总用量 | 是 | 否 | 否 | 否 |
| 管理全局账号停用状态 | 是 | 否 | 否 | 否 |
| 管理平台 AI Gateway 密钥 | 是 | 否 | 否 | 否 |
| 查看本工作区成员名单 | 否 | 是 | 是 | 是 |
| 管理邀请 | 否 | 是 | 是 | 否 |
| 移除本工作区成员 | 否 | 是 | 否（当前 API 仅 owner） | 否 |
| 调整成员在本工作区的角色 | 否 | 是 | 否 | 否 |
| 全局停用账号 | 否 | 否 | 否 | 否 |
| 设置应用访问名单 | 否 | 是 | 否 | 否 |
| 设置 AI 每日请求预算、查看工作区操作日志 | 否 | 是 | 否 | 否 |
| 查看本工作区当日 AI 用量 | 否 | 是 | 是 | 是 |
| 浏览其他工作区业务记录 | 否 | 否 | 否 | 否 |

补充规则：

- 平台角色在服务端判定；隐藏按钮只是界面体验，不能代替 API 授权。
- 用户在某个工作区被移除，只撤销该工作区的成员关系及该空间的应用权限，不得停用其全局账号或影响其他工作区。
- 全局账号停用仅由平台管理员执行；要求输入原因，立即拒绝该账号后续会话请求，并写入平台审计。用户可自行停用/删除账号，但最后一个有效平台管理员不得停用或删除自己。
- 首期不提供平台管理员代入用户身份、业务数据浏览、附件下载或永久删除账号/工作区操作。
- 平台审计记录操作者、动作、目标、时间、结果和原因，不保存密钥、业务字段、附件内容或对话正文。
- 平台 `/api/admin/*` 操作不应被错误写入当前选择工作区的普通审计日志。

## 5. 已确认缺陷与处理要求

| 优先级 | 缺陷 | 处理要求 | 状态 |
| --- | --- | --- | --- |
| P0 | 登录后是孤立对话画面；无工作区选择器、应用列表、成员/用量/日志等入口 | 用户工作台作为默认入口，恢复导航并为已有能力提供可见入口 | 已完成 |
| P0 | 平台后台仅有 AI 配置 API，AI 管理弹窗没有入口，无全局目录 API 或后台 | 建立平台管理员 API、独立页面、权限校验和全局审计 | 已完成 |
| P0 | 前端保留数据表/记录渲染代码，但静态页面缺 `#table-list`、`#records-root` | 恢复手动数据页并覆盖空状态、只读状态与分页 | 已完成 |
| P0 | 工作区“停用成员”会修改全局用户 `disabled`，影响其全部工作区 | 分离“移除空间成员”和“平台停用账号”；修复 UI 文案与服务端语义 | 已完成 |
| P1 | 停用的 owner 无法登录，也无平台恢复账号入口 | 建立平台恢复流程；让停用提示指向真实可执行的恢复路径 | 已完成 |
| P1 | 普通工作区审计只展示第一页；平台管理员操作混入当前工作区审计 | 工作区日志支持分页；平台与租户审计分开存储、授权和展示 | 已完成 |
| P1 | 文档描述的成员/用量/AI 管理界面未连接到主流程 | 更新快速开始与产品评审，只声明真实可使用的路径 | 已完成 |
| P1 | 工作区切换时可能沿用旧应用上下文 | 切换后同步请求头、清理对话及应用/表/记录状态，恢复所选工作区 | 已完成 |

## 6. 分阶段实施与验收

每一阶段按“实现、验证、提交”单独交付；若发现需要改变已确认的权限边界，先更新本文件再继续。项目要求每次修改后提交 Git。

### 阶段 0：文档基线（已完成）

- 更新本方案和当前产品评审，明确已上线代码与计划建设的区别。
- 验收：文档列明两个工作面的目标、导航、权限、缺陷、实现阶段和可操作验收标准；与代码现状一致。

### 阶段 1：平台管理后端（已完成）

- 为平台管理员实现总览、分页的全局用户/工作区/应用元数据、汇总 AI 用量、非敏感运行配置状态 API。
- 实现带原因的用户停用/恢复操作和独立平台审计；`MIAO_ADMIN_EMAILS` 继续作为管理员来源。
- 加固 AI 配置读取/轮换/回退接口：只返回掩码状态；所有全局写操作和越权拒绝进入平台审计。
- API：`GET /api/admin/overview`、`GET /api/admin/runtime`、`GET /api/admin/users`、`PATCH /api/admin/users/:id/status`、`GET /api/admin/workspaces`、`GET /api/admin/apps`、`GET /api/admin/usage`、`GET /api/admin/audit`，以及既有 `/api/admin/ai` 配置路由。
- 验收：非平台用户直接调用所有 `/api/admin/*` 返回 403；分页筛选不跨出 metadata；任何响应中无记录值、附件内容、对话正文和完整密钥；管理员停用账号后用户不能继续使用，恢复后可登录；每次状态变更留有 actor/target/reason/time。

### 阶段 2：平台后台界面（已完成）

- 建设总览、用户、工作区、应用目录、AI 服务和平台审计页面；只向平台管理员显示入口。
- 搜索、分页、加载、无结果、接口错误、确认停用与成功状态均有明确反馈。
- 验收：普通账号无法通过导航或直接访问管理页面获得数据；每个管理动作可由真实 API 持久化并在审计页查到。

### 阶段 3：用户工作台导航与首页（已完成）

- 登录默认显示当前工作区首页、工作区切换和应用目录；fx 对话成为独立入口。
- 恢复应用创建、编辑、打开、归档/恢复和删除的真实数据流；不同 workspace 间不复用页面状态。
- 验收：刷新和重新登录后工作区/应用状态正确；空工作区能引导创建；没有权限的应用不会出现在目录或被 API 打开。

### 阶段 4：应用数据与管理功能接入（已完成）

- 恢复表、记录的手工管理；接通成员与邀请、角色、应用权限、AI 预算/用量、导出和操作日志入口。
- 修复全局停用与工作区移除的语义差异，并加入账号恢复路径。
- 验收：手动和 fx 两条路径使用同一权限规则；viewer 写请求被拒绝；移除成员只影响当前工作区；表格过滤、分页、附件授权下载与文档一致。

### 阶段 5：交付收尾（进行中）

- 更新 API、快速开始、部署和备份文档；运行项目已有适用验证，并在目标环境完成邮件、Gateway、反向代理与恢复演练。
- 待验收：在目标账号检查平台管理员入口和权限，在有多个工作区的账号检查切换与隔离，在真实 Gateway/邮件和备份环境完成联调与恢复演练。

## 7. 实施约束与暂不建设项

- 沿用 Bun + Fastify + PocketBase、原生 JavaScript、现有 PM2 生命周期和 DaisyUI；不引入新前端框架或独立后台服务。
- 真实数据只能由受权限保护的服务端 API 提供，不写死平台统计数字或管理列表。
- 平台用户/工作区/应用目录均采用分页，不因一次拉取全库导致管理页变慢或内存增长。
- 首期不做计费系统、用户模拟登录、业务记录的管理员浏览、直接编辑/删除业务数据、多级平台角色配置或可编辑任意服务器环境变量。
- AI tokens 不等同于供应商账单；平台概览明确标注计量口径，不展示虚构费用。
